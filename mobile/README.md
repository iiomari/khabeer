# خبير على TestFlight — بلا ماك

هذا المجلد يحوّل موقع خبير إلى تطبيق iOS، ويبنيه **GitHub Actions على جهاز macOS سحابي**
ثم يرفعه إلى TestFlight. لا تحتاج جهاز ماك ولا Xcode على جهازك إطلاقًا.

---

## ما الذي يفعله التطبيق فعلًا؟

الموقع مبني بالكامل على الخادم (مصادقة، قاعدة بيانات، Server Actions)، فلا يمكن تصديره
ملفات ثابتة تُحزَم داخل التطبيق. لذلك التطبيق **غلاف أصلي يفتح الموقع المنشور**:
أيقونة واسم وشاشة بداية ووضع ملء الشاشة، ومحتواه يأتي من `khabeer-inky.vercel.app`.

> **⚠️ اقرأ هذا قبل أن تخطط للنشر في المتجر**
>
> بند آبل **4.2 (الحد الأدنى من الوظائف)** يرفض التطبيقات التي هي موقع مُغلَّف بلا قيمة أصلية.
>
> | المسار | العدد | المراجعة |
> |---|---|---|
> | **TestFlight داخلي** | ١٠٠ مختبِر من فريقك | **لا توجد مراجعة** ← هذا مسارك |
> | TestFlight خارجي | ١٠٬٠٠٠ | Beta App Review — يطبّق ٤.٢ |
> | App Store | الجميع | مراجعة كاملة — سيُرفض بشكله الحالي |
>
> للوصول إلى المتجر لاحقًا تحتاج ميزات نظام حقيقية: إشعارات فورية للحجوزات،
> دخول بـ Face ID، رفع شهادات بالكاميرا، عمل جزئي بلا إنترنت.

## الإعداد — مرة واحدة فقط (٢٠–٣٠ دقيقة)

### ١) سجّل التطبيق في App Store Connect

اذهب إلى [appstoreconnect.apple.com](https://appstoreconnect.apple.com) ← **My Apps** ← **+**

| الحقل | القيمة |
|---|---|
| Platform | iOS |
| Name | خبير |
| Primary Language | Arabic |
| Bundle ID | `sa.khabeer.app` — أنشئه أولًا في [Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/identifiers/list) |
| SKU | `khabeer-001` |

### ٢) أنشئ مفتاح App Store Connect API

**Users and Access** ← **Integrations** ← **App Store Connect API** ← **+**

- **Name**: `GitHub Actions`
- **Access**: `App Manager` ← ضروري، أقل من ذلك لن يستطيع الرفع

نزّل ملف `.p8`. **ينزل مرة واحدة فقط ولا يمكن إعادة تنزيله.** واحفظ من نفس الصفحة:
- **Key ID** (عشرة أحرف)
- **Issuer ID** (معرّف طويل أعلى الصفحة)
- **Team ID** — تجده في [حسابك](https://developer.apple.com/account) تحت Membership Details

### ٣) ضع الأسرار في GitHub

المستودع ← **Settings** ← **Secrets and variables** ← **Actions** ← **New repository secret**

| الاسم | القيمة |
|---|---|
| `APPSTORE_KEY_ID` | الـ Key ID |
| `APPSTORE_ISSUER_ID` | الـ Issuer ID |
| `APPSTORE_PRIVATE_KEY` | **محتوى ملف `.p8` كاملًا** بما فيه سطرا `-----BEGIN/END PRIVATE KEY-----` |
| `APPLE_TEAM_ID` | الـ Team ID |

### ٤) شغّل البناء

المستودع ← **Actions** ← **iOS · TestFlight** ← **Run workflow**

يستغرق ١٥–٢٥ دقيقة. عند نجاحه تجد البناء في App Store Connect تحت **TestFlight**
بعد ١٠–٢٠ دقيقة من المعالجة.

### ٥) أضف المختبِرين

**TestFlight** ← **Internal Testing** ← أنشئ مجموعة ← أضف بريد كل مختبِر.
يصلهم رابط دعوة، ويثبّتون تطبيق TestFlight من المتجر ثم يفتحون الرابط.

## أسئلة متوقعة

**هل يحتاج التطبيق إعادة بناء كلما حدّثت الموقع؟**
لا. المحتوى يُحمَّل من الخادم، فأي نشر على Vercel يظهر فورًا داخل التطبيق.
تعيد البناء فقط عند تغيير الأيقونة أو الاسم أو إضافة ميزة أصلية.

**كم يكلف البناء السحابي؟**
دقائق macOS على GitHub Actions تُحسب بمعامل ١٠×. البناء الواحد ≈ ٢٠ دقيقة ≈ ٢٠٠ دقيقة
من حصتك. الحساب المجاني يعطي ٢٬٠٠٠ دقيقة شهريًا للمستودعات الخاصة — أي ما يقارب ١٠ عمليات
بناء شهريًا مجانًا. المستودعات العامة مجانية بالكامل.

**فشل البناء عند التوقيع — ماذا أفعل؟**
غالبًا صلاحية المفتاح. تأكد أن دور المفتاح **App Manager** لا `Developer`،
وأن `sa.khabeer.app` مسجّل فعلًا كـ Identifier في حسابك.

**هل أستطيع تغيير الموقع الذي يفتحه التطبيق؟**
نعم — عند تشغيل الـ workflow ضع الرابط في الحقل `site_url`، أو عدّل القيمة الافتراضية
في `capacitor.config.ts`.
